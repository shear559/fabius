# LongMemEval (oracle): harness for fabius-archivum
**Benchmark.** LongMemEval (Wu et al., ICLR 2025) in the oracle setting: only the evidence sessions (1 to 6, dated) come before each question. 500 questions in 6 types, 30 of them abstention (`*_abs`). Data and code are MIT-licensed.
**Source and pin.** HF `xiaowu0162/longmemeval@2ec2a557f339`, file `longmemeval_oracle`, SHA-256 `821a2034d219…dac095d38620c`. These are the same bytes as `longmemeval-cleaned@98d7416c` `longmemeval_oracle.json`, because the 2025-09 cleaning changed only the _s and _m haystacks. Official code: `github.com/xiaowu0162/LongMemEval@9e0b455f`. `run_generation.py`, `evaluate_qa.py`, `print_qa_metrics.py` and `LICENSE` are copied unmodified into `official/` and git-blob-checked on every run. All pins are in `source.json`.
**Sample.** All 500 ids are sorted, shuffled with `numpy.random.default_rng(20261006).permutation`, and the first N = 120 are kept: temporal 34, multi-session 26, knowledge-update 19, single-session-assistant 17, single-session-user 15, preference 9 (8 of the 120 are abstention). `python prepare.py` rebuilds `items.jsonl` and `source.json` identically.
**Prompt.** Built by the authors' own `run_generation.prepare_prompt` with the README-recommended reader `full-history-session 1000 json false con`. Sessions are sorted by date and `has_answer` is removed. Each session is `\n### Session {i}:\nSession Date: {date}\nSession Content:\n\n{json.dumps(turns)}\n`, inside: `I will give you several history chats between you and a user. Please answer the question based on the relevant chat history. Answer the question step by step: first extract all the relevant information, and then reason over the information to get the answer.\n\n\nHistory Chats:\n\n{history}\n\nCurrent Date: {question_date}\nQuestion: {question}\nAnswer (step by step):`. Answers are free-form (the judge reads them), so no answer format is imposed. Length: mean 30,011 chars, about 6.6k tokens (o200k; median 6.4k, max 23.9k), so about 0.79M input tokens per arm.
**Scoring (official LLM judge; nothing here calls a model).** Step 1: `python score.py responses.jsonl out.jsonl` writes `out.judge_prompts.jsonl` (rename with `--judge-prompts`): one official `evaluate_qa.get_anscheck_prompt(type, question, answer, response.strip(), abstention='_abs' in id)` per item, plus placeholder rows in `out.jsonl` (`passed: null`). Step 2: send each `judge_prompt` as the only user message (official judge: gpt-4o-2024-08-06, temperature 0, max_tokens 10) and save `{"item","judgement"}` lines. Step 3: `python score_from_judgements.py out.judge_prompts.jsonl judgements.jsonl out.jsonl` sets `passed = int('yes' in judgement.strip().lower())` (the official rule) and prints the print_qa_metrics summary: per type, task-averaged, overall, abstention. Secondary, not official: `string_match` (SQuAD-normalised gold appears in the response), `verdict_strict`, `verdict_ambiguous`.
**Self-check** (`python selfcheck.py` writes `selfcheck.json`; no model involved). Verified: the pinned code; reader prompts 120/120 and judge prompts 360/360 byte-identical to the official functions imported as ordinary modules; all 500 items build untruncated, in date order, with no `has_answer` leak; the verdict rule on 12/12 cases; the item join is exact and bad input is rejected; `string_match` passes 103/103 gold answers and 0/103 clearly wrong answers (another question's answer). Pending, the LLM-judge leg: judge `selfcheck/{gold,wrong}.judge_prompts.jsonl` with the study's judge, save the replies as `selfcheck/{gold,wrong}.judgements.jsonl`, and re-run. Expect nearly all gold yes and nearly all wrong no, and explain each exception.
**Deviations.** The judge is whatever model the study uses (the authors' judge is GPT-4o; agreement with it is not measured here). The reader runs in the study harness, not the API at temperature 0 with an 800-token cap. Reading is single-call `con` (README default), not the two-call `con-separate`. N = 120 of 500, so per-type accuracies are coarse (preference n = 9, abstention n = 8).
