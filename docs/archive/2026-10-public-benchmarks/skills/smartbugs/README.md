# SmartBugs-curated harness (skill under test: fabius-catena)
- **Benchmark**: SmartBugs-curated (Durieux et al., ICSE 2020), 143 vulnerable Solidity contracts, each annotated with its DASP-10 category and vulnerable line numbers.
- **Source / pin**: github.com/smartbugs/smartbugs-curated @ `230e649123477eff332742a59a1c7cc6dc286cab`. This directory is that clone (upstream README: `git show HEAD:README.md`). `prepare.py` reads the pinned git objects. The SHA-256 of `vulnerabilities.json` (`2a7c1194…`) and of every contract is in `source.json`.
- **N / sampling**: N = 143 = every annotated contract. ids = repo paths, sorted, then `numpy.random.default_rng(20261006).permutation`, first 143 (the `items.jsonl` order).
- **Prompt**: `{source}` = the contract minus the SmartBugs header comment (@source/@author/@vulnerable_at_lines) and every `// <yes> <report> …` marker line (they are the answer key). Each kept line is rendered as `<n> | <code>`, no file name, everything else verbatim. Exact template: ````"Below is a Solidity smart contract. Each line is prefixed with its line number.\n\n```solidity\n{source}\n```\n\nIdentify the most important vulnerability in this contract and classify it with exactly one of these 10 DASP category labels:\n- reentrancy (Reentrancy)\n- access_control (Access Control)\n- arithmetic (Arithmetic Issues)\n- unchecked_low_level_calls (Unchecked Return Values For Low Level Calls)\n- denial_of_service (Denial of Service)\n- bad_randomness (Bad Randomness)\n- front_running (Front-Running)\n- time_manipulation (Time Manipulation)\n- short_addresses (Short Address Attack)\n- other (Unknown Unknowns: any vulnerability not covered by the labels above)\n\nEnd your answer with exactly these two lines:\nCategory: <one label from the list above>\nLines: <comma-separated line numbers of the vulnerable code>"````
- **Scoring** (`score.py`): the last line starting `Category:` (markdown allowed; else the last `category:` anywhere) must name exactly one label: snake_case label, DASP name or SmartBugs marker spelling, case/punctuation-insensitive, bracketed asides and text after a spaced dash ignored. Two labels = hedge = fail. `passed` = that label is one of the contract's annotated categories.
- **Secondary**: `line_hit` = a `Lines:` number (ranges expanded) is an annotated line. `cat_line_hit` = right category at an annotated line of that category (the ICSE-2020 tool-detection criterion). Also `category_pred`, `category_status`, `n_lines_pred`.
- **Self-check** (`python selfcheck.py` → `selfcheck.json`, all expectations met, no failures to explain): passing sets: answers from vulnerabilities.json 143/143 (line_hit and cat_line_hit 143/143); the in-file `<yes> <report>` markers verbatim 143/143; DASP names + markdown + a line range 143/143. Failing sets: every wrong label (after the gold label in prose) 0/1285 with line_hit 0; two hedged labels 0/143; gold only in prose with no answer lines 0/143; empty 0/143. Prompt checks: no prompt contains markup or "smartbugs"; all 224 gold lines show the annotated code; a fresh run reproduces every prompt, gold and the sampling order, and `items.jsonl` matches the SHA-256 in `source.json`.
- **Deviations**: SmartBugs scores tools on every finding by category + line; here one "most important" answer per contract, primary = category only (study spec), official criterion = `cat_line_hit`. Markup removed and lines renumbered (gold remapped and verified). The one contract stored twice with identical code (0x627fa62c… in reentrancy/ and unchecked_low_level_calls/) accepts the union of both annotations. Original comments and identifiers are kept, and in some contracts they name the bug (e.g. `// INSECURE`, `Single transaction overflow`).
