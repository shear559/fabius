# FinQA harness for fabius-fortuna (markets and finance)
- **Benchmark.** FinQA (Chen et al., EMNLP 2021): numerical reasoning over S&P 500 annual-report pages (text plus one table); public test split, 1,147 questions. This directory is the upstream clone; its own README is `git show HEAD:README.md`.
- **Source + pin.** github.com/czyssrs/FinQA @ `0f16e2867befa6840783e58be38c9efb9229d742`, `dataset/test.json` sha256 `831dbfb2e785dbc227f895ce3f24046433467aec67b09db2bd6ac7692a8a30dc`; `prepare.py` refuses any other commit or hash. Details in `source.json`.
- **Sample.** N = 200 of 1,147 eligible (every test id whose `qa.exe_ans` is a finite number or yes/no): ids sorted, `numpy.random.default_rng(20261006).permutation`, first 200, giving 197 numeric and 3 yes/no golds. `python prepare.py` rebuilds `items.jsonl` byte-identically.
- **Prompt template.** `{pre_text}`/`{post_text}` are the dataset's sentences joined by spaces, verbatim (FinQA's tokenized lower-case text); `{table}` is `table` as a markdown pipe table with row 0 as header, as FinQA's own table_row_to_text treats it:
  `Read the following text and table, and then answer a question.\n\n{pre_text}\n\n{table}\n\n{post_text}\n\nQuestion: {question}\n\nGive your final answer on the last line in the form "Answer: <value>", where <value> is a single number, or yes or no if the question asks for a yes/no answer.`
- **Scoring** (`python score.py responses.jsonl out.jsonl`, gold = `qa.exe_ans`). Answer text = rest of the last line-initial `Answer:` (or `Final answer:`, or an `Answer` heading); fallbacks are mid-line `answer:`, then `answer is`, then `\boxed{}`; no marker fails. yes/no if it starts so (true/false accepted). Otherwise its first number (after the last `=` if any), ignoring markdown, LaTeX, $, commas and %; a `-`/`−` touching the number or its `$`, or `(x)`, makes it negative (`- 5` is read as a bullet); a scale word (thousand to trillion, k/m/bn) is tried both ignored and applied. A number v passes if any of v, v/100, v*100 is within max(1% of |gold|, 0.01) of gold. yes/no must match exactly. Sign counts.
- **Secondary fields.** `format_ok`, `extracted`, `pred`, `form` (which reading matched), `passed_rel1pct` (same match without the 0.01 floor) and `sign_flip_match`.
- **Self-check** (`python selfcheck.py` writes `selfcheck.json`):
  - FinQA's official executor replays all 200 gold programs exactly to `exe_ans`.
  - Gold written in 8 response styles: 1600/1600 pass. Parser cases: 29/29.
  - The dataset's human `qa.answer`: 182/200 pass (1049/1147 on the full test set). Every sample failure is reviewed: 9 wrong `exe_ans` (program bugs), 2 `qa.answer` typos, 5 blank, 2 sign conventions.
  - Wrong sets: another item's gold passes 5/200 (4 of them only through the 0.01 floor); no answer, unparseable and yes/no swap pass 0/200.
- **Deviations.** The official metric executes a predicted DSL program and needs an exact result (rounded to 5 dp); free text instead gets the lenient match the spec sets. Its 0.01 absolute floor applies to ratio golds (107/197 numeric sample golds have |gold| < 1), so up to ±1 percentage point passes: gold×1.05 passes 53/200 and gold×1.10 passes 28/200, against 0/200 for `passed_rel1pct`. The percent forms also accept slips of exactly 100×. 9/200 golds are demonstrably wrong (listed in `selfcheck.json`), so a fully correct model scores at most about 95.5%.
