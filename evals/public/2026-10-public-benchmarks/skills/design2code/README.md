# Design2Code harness (skill: fabius-decor, UI and design)
**Benchmark.** Design2Code (Si et al. 2024, arXiv:2403.03163): rebuild a real webpage from its screenshot as one HTML+CSS file (484 C4 pages). **Pin:** HF `SALT-NLP/Design2Code` @ `e2f61f6e9d9b5ee201b81d8e0ae4d37aa13f8f25`; metric code `NoviScl/Design2Code` @ `7a575e4c33f417c4be5c64072b8f5798de0d0f99`, vendored in `scorer/official/`. Every file SHA-256, the scorer image and its lock files are in `source.json`.
**Sample.** N=80 of 484: `sorted(ids)` (string sort) → `numpy.random.default_rng(20261006).permutation` → first 80 (`prepare.py`). The model opens `screenshots/<id>.png`; the gold is `refs/<id>.html` (+ `refs/rick.jpg`).
**Prompt.** The official direct-prompting instruction (`prompting/gpt4v.py`, `claude.py`) word for word, except line 2 → `A user will provide you with a screenshot of a webpage: the PNG image file at <abs path> (view it with your file-reading tool).` and the last line → ``Respond with the content of the HTML+CSS file, as one complete HTML document in a single ```html code block:``.
**Scoring.** `python score.py responses.jsonl out.jsonl` (needs Docker; builds `fabius-design2code-scorer:1.0` once). Extraction: the longest ```` ``` ````-fenced block containing `<html`, `<!doctype` or `<body` (else the whole reply), then the official `cleanup_response`. The official `visual_eval_v3_multi` then runs offline (`--network none`, non-root): official pre-processing, Playwright Chromium full-page renders of prediction and reference at 1280 px, OCR-free text blocks, Block-Match, Text, Position, Color (CIEDE2000), CLIP ViT-B/32 on CPU; `score` = mean of the five. A file of 80 responses takes roughly 10–40 min at the default `--jobs 6`.
**Outcome.** PRIMARY = the continuous `score`: compare paired per-item means between arms, and read `position`, `color` and `clip` too, because the total is text-heavy (a copy of the right text with no design at all scores a median 0.806; the official GPT-4V outputs score a median 0.866). `passed` (secondary) = `score ≥ 0.806` = median gold self-score (1.000) − margin, where the margin (0.194) is what a perfect copy loses when all styling, layout and images are stripped. A pass keeps more of the design than plain text would.
**Self-check** (`make_selfcheck.py` → `selfcheck.json`): gold 80/80 pass (min 0.989); another benchmark page 0/80 (max 0.753); blank page 0/80; prose-only reply 0/80; design-free text 39/80. On the official released GPT-4V predictions, the per-item scores match the official released scores (Pearson r = 0.990, mean |Δ| = 0.005, means 0.854 vs 0.856). Extraction tests 8/8. A second full gold run gave identical scores on 80/80 and `passed`=1 on 80/80 end to end.
**Deviations.** (1) `score` skips one official pre-processing step, the repetition heuristic `check_repetitive_content`: it counts pretty-printed whitespace as "repetition" and truncated 47/80 gold references to near-blank pages (official-pipeline gold median 0.17), yet never fires on the 484 official GPT-4V outputs. The unmodified value is kept as `score_official_pipeline`, with `repetition_truncated`. (2) Offline rendering, so web fonts and remote images load on neither side. Fonts are DejaVu without Liberation, which reproduces the published screenshots: 47/80 references re-render at the same size with <0.1% of pixels off by >64/255, and 29 of the other 33 use `@font-face` web fonts. (3) Whitespace-only IndentationError fix in `visual_score.py` (`scorer/official-indent-fix.patch`). (4) An exception or the 3600 s per-item cap scores 0 (`scorer_ok=false`), as the official catch-all did. (5) The model opens the PNG with a file tool instead of receiving an API image block. (6) Each prompt holds the absolute PNG path, which contains the local user name and `fabius-benchmark`; `prepare.py --image-root DIR` relocates it.
