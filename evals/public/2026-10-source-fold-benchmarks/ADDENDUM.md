# Source-fold continuation — addendum v1.1, fixed before the first scored run

**2026-10-11.** The owner asked for the tests to continue at full force and to cover the capabilities added in the meantime. This addendum takes `PROTOCOL.md` (Codex, 2026-10-10, commit `d077cef`) as the registered design — the three contemporary arms, the eleven benchmarks and their frozen samples, the confined `Read` variant, the 33-contrast family and its statistics — and fixes everything that protocol left open, plus every point where execution departs from it. Nothing here changes an arm, a sample, a prompt, an endpoint or a verdict rule. It is committed and pushed before any scored run; the harness it names is committed beside it.

## What is fixed here

1. **Budget record.** The owner's instructions of 2026-10-07 ("upload everything, spend everything; at Sunday's reset at most we continue") and 2026-10-11 ("continue the tests at full force"). Ceilings as in the earlier study: the weekly meter stops the study at 0.97 (whole items only); the five-hour meter pauses new items at 0.90 until its reset. Meters are read from every run's last usage event; the canaries served as the permitted non-scored probes. Readings at launch: weekly 0.03, five-hour 0.14 (the weekly meter reset on 2026-10-11 at 12:00 Asia/Jerusalem). Hard count: the 6,501 scheduled invocations plus at most two infrastructure retries per attempt, as registered.
2. **Harness.** The earlier study's harness (`harness/`, the copy committed here), extended, runs the cohort; the serial controller prepared in this folder (`controller.py`, `runtime.py`, `scoring.py`, their tests) is kept as Codex's preparation and is not executed. Changes made for the cohort, all in the committed copy: `cohort.py` (arms, owners, package directories, confined-read rules, the loader for `schedule.jsonl`); `claude_run.py` (an arm carries its own plugin directory; every `Read` call and its result are recorded); `runner.py` and `swe_runner.py` (cohort mode; the three arms of a block run back to back in the block's scheduled order); `score_ifeval.py` (the cohort's arms); every module's data root from `FB_ROOT`; `collect.py` and the scorers (package reads per run); `build_packages.py`; `judge_longmemeval.py` and `calibrate_judge.py`; `analyze_fold.py`. Execution is parallel: up to 6 workers per single-turn benchmark, 2 for SWE-bench, several benchmarks at once. Attempts live in immutable `attempt-<n>/` directories, never a shared ledger; the two-retry rule and the classification of attempts are the registered ones.
3. **Data root.** `~/Documents/fabius-benchmark-fold/`: copies of the frozen datasets, scorer code and SWE-bench pins; the interpreters of the earlier study reused read-only (`PYTHONDONTWRITEBYTECODE=1`); nothing is written into the earlier study's folders.
4. **Packages.** Built by `build_packages.py` from `INPUTS.json`: every listed path extracted from the named commit (`ce34f26` for `old`, `6fb0ab0` for `candidate`), 124 and 128 files, every file's SHA-256 and size checked, and both manifest digests recomputed in Codex's canonical form and equal to `INPUTS.json` (`build-report.json`). Placed at `/private/tmp/fbpkg/<arm>/fabius`, outside the data root and outside every denied path. The two packages differ in four added and ten changed reference files and in nothing else.
5. **Confined Read, the exact rule.** Single-turn runs: `--tools Skill,Read`, `--allowedTools Skill 'Read(//<run dir>/**)'` plus, in a package arm, `'Read(//private/tmp/fbpkg/<arm>/fabius/**)'`; the earlier study's denies stay (`Read(//Users/**)`, `Edit(//Users/**)`, `Write(//Users/**)`, `Read(//private/var/folders/**)`); any other path is refused by the non-interactive permission check. SWE-bench keeps its registered profile (Read, Edit, Write, Glob, Grep, TodoWrite, Skill, wrapper-only Bash). Canary (`canaries/confined-read/`, three arms, one prompt asking for a package file, `/etc/hosts` and a file in the run directory): the package arms read their own contract (delivered, 423 and 1,299 characters), `/etc/hosts` was refused in every arm, the run-directory file was delivered in every arm; init skill counts 0 / 15 / 15; first-turn prompt 6,681 tokens in the baseline and 12,632 in both package arms (the invoked contract). SWE canary (`canaries/swe/`, one task, the candidate arm): 15 skills in context, the disciplina contract injected (15,808 first-turn tokens), one host shell command refused, a three-line patch produced in 8 turns.
6. **Invocation per benchmark** (the owner column of the protocol's table): `/fabius` on IFEval; `/fabius:fabius-disciplina` SWE-bench; `-parcus` HumanEval+; `-praesidium` CyberSecEval; `-scientia` LAB-Bench; `-fortuna` FinQA; `-doctrina` DS-1000; `-catena` SmartBugs-curated; `-cohors` BFCL; `-archivum` LongMemEval; `-decor` Design2Code. The same string in both package arms; the baseline gets the task verbatim.
7. **Design2Code assets.** The frozen prompt names the screenshot by an absolute path; in every arm the screenshot is copied into the run directory as `<item>.png` and that path slot alone is substituted (`cohort.design2code_prompt`), so every arm reads the same bytes from the same kind of place. The primary endpoint is the continuous official score; `passed` (score ≥ 0.806, the registered secondary threshold) is reported as a secondary only. The scorer's self-check stands: the gold pages score 1.0 against themselves, text-only transcriptions 0.806, unrelated pages 0.52.
8. **LongMemEval judge, a declared substitute.** No OpenAI key exists on the machine that runs this study, so the official judge (`gpt-4o-2024-08-06`) cannot be called, and the protocol forbids a silent substitution. The substitute: `claude-sonnet-5-5` in a tool-less, single-turn headless Claude Code session with the same clean-context flags as every run, the official judge prompt (built by the authors' own code, byte-identical, `selfcheck.json`) as the only user message, no package loaded, no knowledge of the arm; the reply is the judgement and the official rule applies (`'yes' in reply.lower()`). Calibration before any arm is judged (`calibrate_judge.py`, `results/longmemeval-judge-calibration/`): GOLD = the gold answer as the hypothesis (abstention items: an explicit abstention); WRONG = the gold answer of another item of the same question type. Acceptance, fixed before judging: GOLD pass rate ≥ 0.95 and WRONG ≤ 0.05 on the answer-type question types; the nine `single-session-preference` items carry a grading rubric, not an answer, as their gold, so they cannot be gold-calibrated and are reported separately. Result (run 2026-10-11 20:31–20:38, 360 judge calls): GOLD 111 of 111 answer-type items judged correct in each of two independent passes, WRONG 0 of 120 judged correct, repeatability 119 of 120 items identical between the two GOLD passes (the one change is a preference item). The preference items' rubric-as-answer control: 1 of 9, then 0 of 9. Accepted. The judge's repeatability on GOLD (two independent passes) is reported with it. Temperature cannot be set through Claude Code; the judge is run once per response, and the primary endpoint is that single judgement.
9. **Schedule.** `schedule.jsonl` as committed by Codex (SHA-256 `138fb13998ecda04…`, seed 20261010): the item order of every benchmark, and the arm order of every item/sample block, are used as given. A block is all three arms of one item (one sample on SWE-bench), run back to back; benchmarks run concurrently; a budget stop ends every benchmark at whole blocks and the realised n is reported. IFEval prompt 143 is included.
10. **Analysis** (`analyze_fold.py`): the 33 contrasts in one family, Holm over the complete family, an incomplete contrast keeping its place with p = 1; binary single-turn endpoints → exact McNemar and Newcombe's hybrid-score interval; SWE-bench (two samples) → paired sign-flip test and a BCa interval stratified by repository; Design2Code → paired mean difference of the continuous score, sign-flip test, BCa interval. Verdicts from the Holm-adjusted p alone: GAIN / LOSS at p ≤ 0.05; on the binary single-turn benchmarks TIE when the 90% interval lies inside ±5 points and NON-INFERIOR when the 95% lower bound is above −5 points; INCONCLUSIVE otherwise, and always so on SWE-bench and Design2Code short of GAIN / LOSS (no margin is invented there). Efficiency (cost, tokens, time, turns) per contrast as geometric-mean ratios with BCa intervals, descriptive. Exposure per package arm: first-turn prompt growth over the same item's baseline (≥ 2,500 tokens = the contract was injected) and the package files each run read, with whether each read was delivered or refused and its length.
11. **Wording.** The earlier study's permitted-wording rules apply. Results are attributed to "the frozen candidate `6fb0ab0`" and "the frozen `v3.3.0-sealed` package" under this harness, model and dates; a release that ships the candidate's `skills/`, core documents and manifest unchanged may say so only after a hash comparison with the package measured here.

## Departures from `PROTOCOL.md`

- Parallel execution with several benchmarks at once, instead of the serial controller.
- Attempt directories and the registered two-retry rule, instead of a reservation ledger.
- The LongMemEval judge substitute above, with its calibration, instead of an indefinite pending state.
- Package directories under `/private/tmp/fbpkg/`, outside the data root.
- Exposure evidence is the recorded `Read` tool calls (path, delivered or refused, characters returned) and the first-turn prompt size, as the protocol asks; byte hashes of delivered content are not recorded, since the tool result carries the text and the package files are hashed in `INPUTS.json`.
