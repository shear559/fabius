# Maintenance behavior smoke checks

These forty-five maintainer-authored scenarios exercise the architecture, update, migration, skill-maintenance, acting-agent, design-capture, standing-job, automation-boundary and live-voice references, and — from 3.2.0 — meeting capture integrity, book-length distillation, the prose tell lint, the existing-site SEO audit, reader-fit reporting, judge wiring, the hosted-model tier, audit closure and the generated-media request. The 2026-10-10 source fold adds video evidence, concurrent notebook jobs, offline recovery, geospatial state, composed media, diagram semantics, critique freshness, quality constraints, shared-channel admission and a notes-only near-neighbor. The 2026-10-17 refresh adds twelve source-update failure scenarios. The 2026-10-22 fold adds two change-record scenarios. They are not a benchmark or an estimate of quality gain. Keep them out of runtime prompts except when the maintainer deliberately runs this evaluation.

Run each prompt from `cases.json` with only the relevant current Fabius contracts and references. Use a fresh context without this rubric or previous answers. Preserve the response, model/harness identity when available, date, and SHA-256 of every supplied contract. Supplied facts are the entire test world; no external actions are needed.

A reviewer checks the observable outcome, not whether wording resembles the contract:

Record each verdict with a short quote from the actual response and any omission. A parse check or lexical match cannot grade these criteria. Archive failures as well as successes. A receipt is valid only while every file it lists under `input_files` (contracts, references and this case's prompt) still hashes identically; any case whose input changed after its last run must be rerun before the next release, and a case never reported in any receipt is unrun. Bind the prompt by recording `prompt_sha256` (the SHA-256 of the case's `prompt` string) on each response, so that adding an unrelated case does not invalidate older receipts; a run that recorded the whole `cases.json` hash instead is judged by that hash. `node evals/verify-maintenance-smoke.mjs` computes coverage and freshness from the receipts — a note in development, a failing gate in release mode. Do not aggregate these observations into the historical benchmark panels.
